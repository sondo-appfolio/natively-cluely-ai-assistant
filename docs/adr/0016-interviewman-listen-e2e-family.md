# Dedicated local Electron e2e for InterviewMan listen (not SD overlay)

We need automated coverage of the **interviewman-control-map** on a real Electron overlay, but `e2e:sd-overlay-interview` is a NO-AUDIO SD gate harness (`startOverlaySessionWithoutAudioForE2e` / `__e2e__:arm-sd-overlay-gate`) and must never count as live-STT / listen proof. We add a separate **interviewman-listen-e2e-family** (`e2e:interviewman-listen`) that arms via `__e2e__:arm-listen-meeting` (meeting + listen-transport without capture-device TCC), runs only locally under `RUN_INTERVIEWMAN_LISTEN=1` (no GitHub CI), and keeps Settings sandbox / phone / real mic as out of first-slice scope. Rejected: bolting listen asserts onto the SD suite; defaulting to real `startMeeting` (TCC flaky even locally); putting the suite under Vite `tests/e2e` `page.goto`.
